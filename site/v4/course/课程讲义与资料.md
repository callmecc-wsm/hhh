## 逐章讲稿

### 01 · 从接下一词开始

**00:00 · 先造一台接话机器**

假设我们从零开始，手里没有一个聪明助手，只有一堆文字和一台能算数的机器。先给它一个小任务：看到小猫坐在，猜接下来是什么。你可能想到地毯，也可能想到窗边。这个问题看起来很小，却藏着整门课的入口。因为想接得合理，机器必须逐渐利用语法、事物关系和上下文。接下来，我们会亲手拆开这台机器，看文字怎样变成数字，数字怎样产生预测，预测的错误又怎样改变机器本身。

画面公式：`小猫坐在 → ?`

参考：[1](https://arxiv.org/abs/2005.14165)

**00:31 · 输出是一整排概率**

机器实际给出的，并不是脑海里蹦出的某一个词，而是下一块文本的概率分布。我们暂时把地毯画成百分之五十五，窗边画成百分之二十五，其他可能合起来百分之二十。这些数字只是教学示意。那一小块文本叫做词元，也常叫 token，它不一定恰好是一个汉字或一个词。概率高，表示模型在这个上下文里更倾向于接它，并不表示这句话在现实世界里有同样高的正确率。

画面公式：`Σ p(next token) = 1`

参考：[1](https://arxiv.org/abs/2005.14165) · [2](https://github.com/openai/tiktoken)

**01:00 · 把答案接回输入**

假如这一次选中了地毯，我们把地毯接回原来的句子，再问一次：接下来呢？新的上下文可能让上这个字的概率变高。这样反复运行，同一台机器就能一块一块地写出长文。这叫自回归生成，意思是后面的预测会使用前面已经出现的结果。它并不需要先准备好整篇答案再逐字播放。每次新选择都会改变后续道路，前面走错，也可能让后面越来越偏。至于怎样从概率里选择，我们到推理那章再展开。

画面公式：`p(x₁…xₙ) = Π p(xₜ | x<ₜ)`

参考：[1](https://arxiv.org/abs/2005.14165)

**01:33 · 训练时答案已经在纸上**

但训练和生成有一个关键区别。训练时，我们手里已经有完整句子，小猫坐在地毯上。我们可以遮住后半句，把原文紧接着的那块文本当成答案。于是同一句话的许多位置，都能贡献一道预测题。模型先猜，我们再比较它和原文的差距，最后调整内部数字。生成时，后文还不存在，只能等前一步选出来。训练时怎样同时做很多题又不偷看答案，稍后会用一张三角形的图解释。

画面公式：`input: x₁…xₜ → target: xₜ₊₁`

参考：[3](https://arxiv.org/html/1706.03762v7) · [1](https://arxiv.org/abs/2005.14165)

**02:04 · 我们将走过十二站**

把整条路展开，你会发现有三段。第一段，准备教材，把文字变成数字，再造出能交换上下文信息的网络。第二段，定义什么叫猜得不好，沿着计算过程找到该改哪些数字，让大量机器协作练习。第三段，把会续写的基础模型教成助手，放进真实产品，最后检验它究竟学会了什么。十二个章节就是这条路上的十二站。数学会在真正需要的时候出现，每次只补足下一步所需的直觉。

画面公式：`数据 → 网络 → 误差 → 更新 → 评估`

参考：[4](https://arxiv.org/html/2407.21783v3)

**02:35 · 一个小任务有多大上限**

先留一个问题：如果任务只是预测下一块文字，它是不是只能背句子？停一下想想。答案是，不一定。想在新文章里持续预测得好，学习可复用的结构往往比逐句背诵更有效，但记忆原文和学到规律也可能同时发生。这门课会解释计算机制，不把它等同于人类心智。我们的主线是只用解码器的现代 Transformer；最初论文还包含编码器，那是另一种完整架构，不能把两张结构图直接当成同一个模型。

画面公式：`简单训练目标 ≠ 简单内部表示`

参考：[1](https://arxiv.org/abs/2005.14165) · [3](https://arxiv.org/html/1706.03762v7)

### 02 · 把文字变成训练题

**03:07 · 教材决定练到什么**

现在正式开工。第一步还不是买更多显卡，而是准备合适的教材。网页、书籍和代码等材料进入数据流程之前，要明确来源和使用条件，再做隐私处理、质量过滤和重复检查。一篇文章复制一万次，不会凭空增加一万份知识，却会增加它对训练的影响。还要把考试题隔离出去，否则分数可能只是提前见过答案。选择哪些语言、哪些领域、各占多少比例，本身就在决定模型会在哪些事情上练得更多。

画面公式：`原始语料 → 筛选 → 去重 → 数据划分`

参考：[4](https://arxiv.org/html/2407.21783v3) · [1](https://arxiv.org/abs/2005.14165)

**03:41 · 文字怎样切成小块**

计算机不能直接对一句中文做矩阵运算，所以先要切块。常见的一类方法叫字节对编码，简称 BPE。你可以想象，先从小碎片开始，统计哪些相邻碎片经常一起出现，把最常见的一对合成新块，再重复这个过程。常用片段因而可能变成一个词元，少见片段则保留得更碎。这是在学习一种压缩式的编码规则，不是先读懂词义。画面把小猫、坐在、地毯分别切成块，只为讲解，不保证真实分词器也这样切。

画面公式：`常见相邻片段 a + b → ab`

参考：[5](https://huggingface.co/docs/course/en/chapter6/5) · [2](https://github.com/openai/tiktoken)

**04:15 · 编号不是意义**

切好以后，每种词元在词表里都有一个整数编号。假设小猫是十七号，坐在是四十二号，这些编号只是货架位置，四十二并不比十七更有意义，也没有天然的距离关系。整句话现在变成编号序列。词表大小表示有多少种可选择的小块，上下文长度表示一次允许处理多少个位置，它们是两个不同维度。相同的一段文章，换一个分词器，所需词元数量可能改变，因此上下文容量不能简单等同于汉字数。

画面公式：`text → token IDs → [17,42,86,…]`

参考：[2](https://github.com/openai/tiktoken) · [6](https://huggingface.co/docs/transformers/tokenizer_summary)

**04:47 · 给每块文字一支箭头**

编号接着去查一张大表。每行对应一个词元，每列存一个可以训练的数，这张表叫嵌入矩阵。查到的整行就是词向量。先别把向量想得神秘，它只是一串有顺序的数字，稍后我们会把它画成箭头。从零训练时，这些数通常随机初始化，而不是预先写好猫的定义。随着训练，它们才逐渐适合后面的计算。同一个词元刚查表时拿到相同向量，进入网络之后，才会结合不同上下文变成不同表示。

画面公式：`E ∈ R^(vocab×d); xₜ = E[idₜ]`

参考：[7](https://docs.pytorch.org/docs/2.14/generated/torch.nn.Embedding.html)

**05:19 · 错开一格就有答案**

再看训练题怎样自动产生。假设分词结果依次是小猫、坐在、地毯、上。输入一行放前三块，答案一行放后三块，两行刚好错开一格。在小猫那个位置，目标是坐在；在坐在那个位置，模型可以利用前面的内容，目标是地毯。于是原文自己提供了监督信号，不需要人给每个位置标答案。这里也埋着一个必须解决的问题：完整输入虽然已经放进机器，每个位置却必须挡住自己右侧的内容。

画面公式：`inputs = ids[:-1]; targets = ids[1:]`

参考：[3](https://arxiv.org/html/1706.03762v7)

**05:51 · 许多题装进同一批**

一条序列太少，我们把多条训练序列装成一批，让硬件一起处理，这就是批次。短序列可以补齐长度，但补齐的位置应当从相应注意力和损失计算中排除。也可以把文档装入更紧凑的序列，同时明确边界策略。现在问你：把小猫的编号从十七改成十八，模型就理解得更深了吗？当然没有。如果只是保持一致地换编号和对应表行，计算可以完全不变。真正能学习的，是表里那些数字以及后面的网络参数。

画面公式：`IDs: [batch, length] → X: [batch, length, d]`

参考：[3](https://arxiv.org/html/1706.03762v7) · [7](https://docs.pytorch.org/docs/2.14/generated/torch.nn.Embedding.html)

### 03 · 够用的线性代数

**06:24 · 向量就是有方向的数字**

现在让那串数字变得看得见。二维向量二、一，可以画成从原点向右走两格、向上走一格的箭头。两项数字是它在两条坐标轴上的分量。真实模型的向量常有成百上千个分量，我们没办法完整画出来，只能用二维示意或投影帮助理解。也不要误以为某一维必定代表猫，另一维必定代表温柔。训练得到的特征通常会分散在许多方向上，箭头靠近可以提供线索，却不是一本逐格可读的语义字典。

画面公式：`x = (2,1)`

参考：[7](https://docs.pytorch.org/docs/2.14/generated/torch.nn.Embedding.html) · [3](https://arxiv.org/html/1706.03762v7)

**06:56 · 加权和就是按比例混合**

向量最重要的一种操作，是加权求和。看两支箭头，一支是二、零，另一支是零、二。第一支乘四分之三，第二支乘四分之一，再把对应分量相加，就得到一点五、零点五。几何上，新的箭头落在两个端点之间，更靠近份量大的那一边。你可以把它理解成按比例混合两份信息。只要权重非负且总和为一，结果就不会跑出这些端点围成的范围。这个简单操作，马上就是注意力机制收集信息的核心。

画面公式：`0.75(2,0)+0.25(0,2)=(1.5,0.5)`

参考：[3](https://arxiv.org/html/1706.03762v7)

**07:29 · 点积给匹配打一个分**

下一种操作叫点积。把一、二与三、一对应相乘，再加起来，一乘三加二乘一，结果是五。它把两串数字压成一个分数。几何上，方向相近通常有利于得到较大的正值，方向相反则可能得到负值，但长度也会影响结果。因此，点积不能直接被叫作纯粹的相似度。如果我们先学会把信息投影到合适方向，再用点积比较，就能得到一种可训练的匹配分数。这正是下一章给上下文分配权重的起点。

画面公式：`q·k = 1×3 + 2×1 = 5`

参考：[8](https://docs.pytorch.org/docs/2.14/generated/torch.matmul.html) · [3](https://arxiv.org/html/1706.03762v7)

**08:02 · 矩阵是批量换一种表示**

把许多行向量摞起来，就得到矩阵。假设四个词元，每个有三个分量，输入矩阵就是四行三列。再乘一个三行两列的权重矩阵，结果会变成四行两列。每个输出数，都来自输入的一行和权重的一列做点积。中间那个三必须对得上，因为对应相乘需要同样多的项。你不用背复杂的乘法表，只需要抓住这幅画面：每个词元都经过同一台混合器，从三个输入分量，生成两个重新组合的分量。

画面公式：`X[4×3] · W[3×2] = Y[4×2]`

参考：[8](https://docs.pytorch.org/docs/2.14/generated/torch.matmul.html) · [9](https://docs.pytorch.org/docs/2.14/generated/torch.nn.Linear.html)

**08:34 · 参数是可以调的混合比例**

再把镜头推近这台混合器。权重矩阵里的每个数，都规定某个输入分量对某个输出分量贡献多少。把一个数从零点二改成零点三，就改变了这条连接的影响。所谓数十亿参数，主要就是大量这样的可调数字，并不是数十亿条人写的知识卡片。一次前向计算时，参数暂时固定，变化的是输入和中间结果；训练更新时，才会根据误差修改参数。把这两个时间尺度分开，后面就不会把聊天和学习混为一谈。

画面公式：`yⱼ = Σᵢ xᵢWᵢⱼ + bⱼ`

参考：[9](https://docs.pytorch.org/docs/2.14/generated/torch.nn.Linear.html)

**09:05 · 为什么还要把直线折弯**

最后问一个问题：把一百个线性变换接在一起，会不会天然获得特别复杂的能力？停一下。如果中间没有非线性，它们仍然可以合并成一个线性变换，就像连续旋转和拉伸仍是一种整体变换。加入激活函数以后，情况才变了。例如最简单的整流函数，把负数变成零，正数保留，让输入经过不同区域时出现不同响应。真实模型会用更适合训练的激活设计，但你已经理解了动机：让网络能够表达更复杂的条件关系。

画面公式：`ReLU(x)=max(0,x)`

参考：[10](https://docs.pytorch.org/docs/2.14/generated/torch.nn.ReLU.html) · [3](https://arxiv.org/html/1706.03762v7)

### 04 · 注意力怎样搬运信息

**09:39 · 它需要从哪里找信息**

有了向量，问题才真正开始。同一个它，可能指猫，也可能指杯子，只查词表显然不够。看这句话：小猫喝完牛奶，因为它很饿。当模型处理它这个位置时，需要从左边的上下文带入有用信息，我们希望其中包括小猫。请注意，它此时不能偷看右边的很饿。画面连接它和小猫，只是帮助理解的一种关系示意，并不声称真实模型的某个头一定这样工作。注意力要解决的，就是让每个位置按当前需要，从可见位置收集信息。

画面公式：`当前位置 ← 可见上下文的信息`

参考：[3](https://arxiv.org/html/1706.03762v7) · [11](https://arxiv.org/abs/1902.10186)

**10:13 · 同一向量分成三个角色**

具体怎样收集？我们让每个输入向量分别乘三组可学习矩阵，得到查询、键和值，通常写成 Q、K、V。查询可以类比我现在在找什么，键可以类比我有哪些特征可供匹配，值则是匹配之后实际拿走的信息。它们不是人预先填好的标签，而是三种不同的数值投影。查询和键负责算分，值负责被混合。三者在自注意力里都来自同一段序列，这个自字，说的就是信息来源，不是在说模型产生了自我意识。

画面公式：`Q=XWq; K=XWk; V=XWv`

参考：[3](https://arxiv.org/html/1706.03762v7)

**10:46 · 先算分，再稳定尺度**

我们来算一次真的。为便于演算，查询取二、零、零、零，三个键的第一项分别是二、一、零，其余项都是零。做点积，分数就是四、二、零。但注意力还会除以键维度的平方根。这里维度是四，平方根是二，所以得到二、一、零。为什么要除？在一些常用统计假设下，维度越大，点积的波动越大，后面的概率容易过分尖锐。这个缩放让数值尺度更稳定，它不是把所有分数强行限制在零和一之间。

画面公式：`scores=(4,2,0)/√4=(2,1,0)`

参考：[3](https://arxiv.org/html/1706.03762v7)

**11:22 · 把分数变成混合比例**

接下来需要把二、一、零变成非负、总和为一的比例。这里用到 softmax：先分别取自然指数，得到大约七点三九、二点七二和一，再各自除以三者之和。结果约为零点六六五、零点二四五和零点零九。原来最高的分数拿到最多份额，但其他项并不会自动消失。减去所有分数里的最大值再计算，比例仍然一样，还能改善数值稳定性。这里的比例表示内部信息混合的份额，并不是模型对一句话是否正确的自信程度。

画面公式：`softmax(s)ᵢ = exp(sᵢ)/Σⱼexp(sⱼ)`

参考：[12](https://docs.pytorch.org/docs/2.14/generated/torch.nn.functional.softmax.html) · [3](https://arxiv.org/html/1706.03762v7)

**11:56 · 拿权重去混合真正的信息**

现在终于轮到值向量。为了画出来，假设三个值分别是二、零，零、二，以及一、一。用刚才三个比例加权求和，第一维大约是一点四二，第二维大约是零点五八。这就是当前查询从这三处收集来的结果。注意，我们混合的是值，不是键，也不是把三段文字直接拼起来。现实里所有位置都可以同时做这件事，因此把查询、键、值摞成矩阵，就得到屏幕上的一行公式。复杂的名字，最终落在刚学过的点积和加权和上。

画面公式：`Attention(Q,K,V)=softmax(QKᵀ/√d) V`

参考：[3](https://arxiv.org/html/1706.03762v7)

**12:34 · 谁教会它寻找小猫**

那是谁规定它要更关注小猫呢？你可以先猜：是工程师写了一条代词规则吗？通常不是。刚初始化时，这些投影并不聪明。训练中，如果某种信息混合有助于降低预测误差，对应参数就会被逐步调整。不同层、不同头形成的作用也不必符合人的语言分类。注意力图能展示信息流的一部分，却不能单独证明模型为什么给出某个答案。我们现在只算了一个查询，下一章要补上三个关键条件：不能看未来、可以多路收集、还得知道位置。

画面公式：`可学习投影 + 训练信号 → 信息选择`

参考：[3](https://arxiv.org/html/1706.03762v7) · [11](https://arxiv.org/abs/1902.10186) · [13](https://arxiv.org/abs/1908.04626)

### 05 · 注意力如何守住时间顺序

**13:09 · 给未来盖上一块布**

先看这个方阵。横轴是被读取的位置，纵轴是正在提问的位置。如果第三个位置正在预测第四个词，它只能读取前三个位置。我们把右上方代表未来的分数设成负无穷，再做归一化；指数作用后，这些格子的权重就是零。这叫因果遮罩。遮罩必须加在归一化之前，否则剩余权重未必加起来等于一。模型可以看见当前位置，因为它要预测的是下一个词，并不是猜自己。

画面公式：`A = softmax(QKᵀ / √dₕ + M)`

参考：[14](https://arxiv.org/abs/1706.03762)

**13:40 · 并行算题不等于偷看**

这里似乎有个矛盾：既然不能看未来，为什么训练还能并行？因为整句话已经在数据里了。我们把小猫、坐在、地毯这些位置一起送入，但让每一行只读取当前位置及其左边。于是第一行做第一道题，第二行做第二道题，一次矩阵运算同时完成许多预测。生成时却不同，下一个词还不存在，必须先选出它，才能把它放进后续上下文。训练并行的是已知句子的不同预测位置。

画面公式：`输入：x₁…xₙ   目标：x₂…xₙ₊₁`

参考：[14](https://arxiv.org/abs/1706.03762) · [1](https://arxiv.org/abs/2005.14165)

**14:10 · 把一个视角拆成多头**

一套查询和键，也许只能抓住部分关系。多头注意力让同一个输入经过多套可学习投影，同时从不同方向读取信息。假设输入有四百个位置，每行八个维度；分成两个头，每头输出四个维度。两份结果沿特征方向拼接，又回到八维，再乘输出矩阵重新混合。这里的数字只是示意。我们不会预先指定哪个头负责语法、哪个负责指代，而且真实的头也未必这样整齐分工。

画面公式：`N×d → h×N×dₕ → N×d → N×d`

参考：[14](https://arxiv.org/abs/1706.03762)

**14:43 · 位置变成旋转角度**

小猫追小狗，和小狗追小猫，词差不多，顺序却改变了意思。我们采用的位置方法叫旋转位置编码。把查询和键的坐标两两配对，看成平面箭头；越靠后的位置，箭头按规定多转一个角度，不同坐标对转速不同。两支箭头做点积时，相对夹角会包含位置差。这样内容和距离一起影响匹配。注意，它作用在查询和键上，并不是简单给输入向量加上一个位置编号。

画面公式：`q′ₘ·k′ₙ = qₘᵀ R(n−m) kₙ`

参考：[15](https://arxiv.org/abs/2104.09864)

**15:13 · 方阵为什么越来越贵**

再把镜头拉回注意力方阵。长度翻倍，行数和列数都翻倍，格子数量就变成四倍。标准全注意力的主要计算因此随长度平方增长，因果遮罩保留半个方阵，也没有改变这个增长规律。快速注意力算法把计算切成小块，在显卡更近、更快的存储中处理，避免完整的大方阵反复搬运。它计算的仍是同一种注意力，并没有把所有两两交互的计算凭空变成线性。

画面公式：`N → 2N    N² → 4N²`

参考：[16](https://arxiv.org/abs/2205.14135)

**15:41 · 遮罩与位置各管什么**

现在停一下：已经用遮罩限制了左右，为什么还要位置编码？先想两秒。遮罩规定哪些位置可以交流；位置编码则让匹配过程知道两个词相隔多远、处在什么顺序。二者解决的问题不同。把这一层串起来，就是投影得到查询、键和值，给查询和键加入旋转位置关系，计算带遮罩的权重，再混合值。不同头各算一次，拼接投影。我们终于有了一个能放进大网络的完整注意力模块。

画面公式：`Q,K,V → RoPE(Q,K) → mask → 加权V`

参考：[14](https://arxiv.org/abs/1706.03762) · [15](https://arxiv.org/abs/2104.09864)

### 06 · 把零件拼成完整 Transformer

**16:13 · 一条主路两次更新**

注意力只是整台机器的一个零件。现在画出一条贯穿画面的主路，里面流动着每个词的向量。我们采用现代常见的预归一化结构：先把输入归一化，送进注意力，再把结果加回原来的向量；随后再归一化，经过前馈网络，再加回来。每次相加都要求两边形状一致。原始论文采用的归一化位置有所不同，还包含编码器。这里讲的是适合逐词生成的仅解码器主线。

画面公式：`H = X + Attn(Norm(X))`

参考：[17](https://arxiv.org/abs/2302.13971) · [14](https://arxiv.org/abs/1706.03762)

**16:43 · 前馈网络会做什么**

注意力负责从别的位置取信息，前馈网络则逐行加工已经取回来的信息。每一行使用同一套权重，先扩展到更宽的特征空间，再压回原来的宽度。我们选用带门控的非线性结构：一条支路产生候选特征，另一条经过平滑激活，再把两条支路逐元素相乘。你可以把它想成根据当前内容调节各个通道的强弱。非线性让这些层不能被折叠成一次普通矩阵乘法。

画面公式：`FFN(X) = [SiLU(XWg) ⊙ XWu] Wd`

参考：[18](https://arxiv.org/abs/2002.05202) · [17](https://arxiv.org/abs/2302.13971)

**17:12 · 为什么还需要主路**

如果每层都彻底重写向量，信息经过几十次加工，很容易变得难以训练。残差连接保留一条直接相加的路径，让模块学习怎样修改现有表示；它也给反向传播提供更直接的路线。归一化则控制每一行数值的尺度。这里使用均方根归一化：平方、取平均、开方，再用它缩放原向量，并乘可学习系数。它通常不减去均值，也不是把每个词的意义洗成完全一样。

画面公式：`RMSNorm(x) = g ⊙ x / √(mean(x²)+ε)`

参考：[19](https://arxiv.org/abs/1910.07467) · [20](https://arxiv.org/abs/1512.03385)

**17:41 · 堆叠不会增加词的数量**

把这样的模块叠上去，输入和输出始终可以保持同样的形状：长度乘特征宽度。变的是向量内容，不是突然多出几个词。低层得到的关联，会成为高层继续组合的材料。不过不要把每层硬解释成人类思维的一步，真实表示通常分散在许多维度和层中。每一层一般拥有自己的参数，但同一层的参数会在不同位置复用。所谓几十亿参数，主要就在这些投影和前馈矩阵里。

画面公式：`X₀ → Block₁ → Block₂ → … → Xᴸ`

参考：[17](https://arxiv.org/abs/2302.13971) · [14](https://arxiv.org/abs/1706.03762)

**18:11 · 向量怎样变回词的概率**

最后一层输出还只是向量。怎样得到地毯这个候选词的概率？先做最终归一化，再乘一个宽度乘词表大小的输出矩阵。原来每行几个千维的表示，就变成覆盖整个词表的一排分数，叫作 logits，也就是未归一化的分数。对每一行做指数归一化，才得到概率分布。输出矩阵有时与输入词嵌入共享权重，有时独立。训练会使用许多位置的分布，而继续生成时，我们通常只拿最后一个位置来选下一个词。

画面公式：`Z = Norm(Xᴸ) Wout ; P = softmax(Z)`

参考：[14](https://arxiv.org/abs/1706.03762) · [21](https://arxiv.org/abs/1608.05859)

**18:43 · 跟着形状走一遍程序**

现在看这段极短的程序：先查词嵌入表，再循环通过一组模块，最后得到词表分数。先暂停想想，如果输入有五个词，最后必须只输出一个向量吗？不必。一次前向计算通常保留五个位置，各有一排词表分数。我们只是根据用途选择哪些位置参与损失或生成。从词编号到向量，从向量到分数，这就叫前向传播。到这里机器已经能计算，但它的参数还没有学会语言。下一步才是教它。

画面公式：`embed(ids) → blocks → norm → logits`

参考：[22](https://github.com/meta-llama/llama/blob/main/llama/model.py) · [17](https://arxiv.org/abs/2302.13971)

### 07 · 把预测的好坏变成一个数

**19:16 · 刚出生的网络不会说话**

让这台完整机器从零启动。大多数矩阵先用经过尺度控制的随机数初始化，归一化系数等参数则可以采用固定初值。为什么不用全零？因为完全相同的单元容易收到相同更新，无法分工。此时输入小猫坐在，输出可能偏向毫不相干的词。它拥有复杂的计算结构，却还没有语言知识。我们需要一个连续的分数，告诉训练程序：这一次分给正确下一个词的概率，到底够不够高。

画面公式：`p(地毯 | 小猫坐在) = 0.10`

参考：[23](https://proceedings.mlr.press/v9/glorot10a.html) · [1](https://arxiv.org/abs/2005.14165)

**19:46 · 为什么使用负对数**

训练文本的下一个词是地毯，我们就取模型给地毯的概率，做负的自然对数。概率是十分之一，损失约二点三零三；提升到二分之一，损失约零点六九三；达到十分之九，只剩零点一零五。注意曲线的形状：把正确答案压到接近零，会被重罚。为什么用对数？整段文本的条件概率原本连乘，取对数就变成逐项相加，也更方便数值计算。这就是这里的交叉熵损失。

画面公式：`L = −ln p(正确的下一个token)`

参考：[24](https://docs.pytorch.org/docs/2.9/generated/torch.nn.CrossEntropyLoss.html) · [1](https://arxiv.org/abs/2005.14165)

**20:16 · 整段文本都是训练题**

我们并不是读完一篇文章，只批改最后一个词。输入和目标错开一个位置，每一行都预测自己的下一个词。把一批文本里所有有效位置的损失相加，再除以有效位置数量，就得到这一步的平均损失。用于补齐长度的空位通常被排除，否则模型会花力气学习无意义的填充。画面上的一行行题目共用同一台网络，因此一次参数更新，会综合许多上下文提出的要求。

画面公式：`Lbatch = Σ L有效位置 / 有效位置数`

参考：[24](https://docs.pytorch.org/docs/2.9/generated/torch.nn.CrossEntropyLoss.html) · [1](https://arxiv.org/abs/2005.14165)

**20:45 · 反馈有多大有方向吗**

知道损失大还不够，我们还要知道每个分数该往哪调。交叉熵和归一化组合后，有一个很漂亮的结果：损失对某个词分数的导数，等于预测概率减去目标标记。正确词的标记是一，其他词是零。比如正确词概率只有零点一，导数就是负零点九；沿反方向更新，就会提高它的分数。其他候选词得到正导数，倾向被压低。这里说的是分数处的局部方向，参数更新还要继续向前追溯。

画面公式：`∂L/∂zᵢ = pᵢ − yᵢ`

参考：[24](https://docs.pytorch.org/docs/2.9/generated/torch.nn.CrossEntropyLoss.html) · [25](https://docs.pytorch.org/tutorials/beginner/blitz/autograd_tutorial.html)

**21:16 · 损失下降意味着什么**

训练若有效，模型会逐渐给真实文本更高的概率。但某一道题并不是唯一合理的续写：小猫也可以坐在沙发上，只是当前样本写的是地毯。模型通过大量不同样本学习分布。常见指标困惑度，就是平均负对数损失取指数，可以粗略理解为预测时的有效不确定性。只有分词方式、评估文本和上下文条件可比时，数字才适合比较。它衡量语言预测，不直接等于推理能力，更不等于事实可靠程度。

画面公式：`Perplexity = exp(平均负对数损失)`

参考：[26](https://huggingface.co/docs/transformers/perplexity) · [27](https://arxiv.org/abs/2109.07958)

**21:49 · 总猜常见词能过关吗**

停一下，如果模型总给常见词很高概率，能不能把损失一路降下去？它确实可能先学到这种捷径，但遇到具体上下文就会付出代价。比如坐在后面需要某类地点，复杂句子还要求主语、时间和前文相互一致。要进一步降低平均损失，就需要利用更多结构。训练目标没有逐条写明语法规则，规则却可以成为降低错误的有效手段。当然，这不保证它最终形成了人类同样的理解方式。

画面公式：`同一目标 → 不同难度的上下文`

参考：[1](https://arxiv.org/abs/2005.14165) · [17](https://arxiv.org/abs/2302.13971)

### 08 · 损失怎样改动数十亿参数

**22:21 · 导数是一根方向指针**

把某一个参数想成旋钮，横轴是旋钮的位置，纵轴是损失。轻轻向右转一点，损失升了还是降了？导数描述的就是这一小段变化率。正导数表示往右走会升高，所以应先向左；负导数反过来。参数很多时，把每个方向的导数组在一起，就是梯度。画面上的山谷只是二维示意，真实空间可以有数十亿个坐标。梯度给出的是当前位置的局部信息，并不提前知道哪里存在全局最优点。

画面公式：`梯度g = ∂L/∂θ`

参考：[25](https://docs.pytorch.org/tutorials/beginner/blitz/autograd_tutorial.html) · [28](https://arxiv.org/abs/1412.6980)

**22:53 · 链式法则只是在乘影响**

先用一个小机器看清链式法则。输入固定为三，参数乘输入得到中间值，再把中间值平方作为损失。参数等于二时，中间值是六。参数多一点，中间值会以三倍速度变化；中间值多一点，平方结果在这里会以十二倍速度变化。因此总影响是三乘十二，等于三十六。反向传播就是从损失出发，把每段局部影响沿链相乘。网络再复杂，也是在重复这一条微积分规则。

画面公式：`u=3w ; L=u² ; dL/dw=2u×3=36`

参考：[25](https://docs.pytorch.org/tutorials/beginner/blitz/autograd_tutorial.html)

**23:25 · 矩阵也可以向后追溯**

回到真实网络。如果一层是输入矩阵乘权重矩阵，上游传来输出的梯度，那么权重梯度就是输入的转置乘上这份梯度。形状也能检查：输入是长度乘宽度，转置后与输出梯度相乘，正好得到权重的形状。一个参数在多个位置被使用，或者通过多条分支影响损失，各条路径的贡献都要相加。自动微分框架记录计算关系，按这些规则反向执行，不需要逐个参数尝试扰动后重新跑模型。

画面公式：`Y=XW ; ∂L/∂W=Xᵀ(∂L/∂Y)`

参考：[25](https://docs.pytorch.org/tutorials/beginner/blitz/autograd_tutorial.html)

**23:57 · 梯度不会自己改参数**

拿到梯度，只完成了测量。最简单的梯度下降，是用参数减去学习率乘梯度。学习率决定这一脚迈多远：太大可能跨过谷底，来回震荡；太小则走得缓慢。更重要的是，一小批文本算出的方向带着采样噪声，不能要求每一步都让全部数据的损失下降。训练循环因此明确分成三件事：前向算损失，反向算梯度，优化器更新参数。反向传播本身并不等于完成一次学习。

画面公式：`θ新 = θ旧 − ηg`

参考：[25](https://docs.pytorch.org/tutorials/beginner/blitz/autograd_tutorial.html) · [28](https://arxiv.org/abs/1412.6980)

**24:29 · AdamW 记住两本账**

大模型常用的 AdamW 优化器，会给每个参数记两本移动账。第一本平滑近期梯度，记录方向；第二本平滑梯度的平方，记录尺度，再据此调整各参数的步幅。这分别叫一阶矩和二阶矩，二阶矩不是二阶导数。因为账本从零开始，还需要偏差校正。权重衰减则让选中的参数轻微缩小，独立于自适应梯度更新实施，这就是名字里那个字母的来历。它是具体更新规则，不是让模型自己理解错误。

画面公式：`Δθ ≈ −η m̂/(√v̂+ε) − ηλθ`

参考：[28](https://arxiv.org/abs/1412.6980) · [29](https://arxiv.org/abs/1711.05101)

**25:01 · 把一次更新变成长期训练**

最后两个常见旋钮是学习率调度和梯度裁剪。训练开始常先逐步升高学习率，让数值过程稳定；后期再降低，做更细的调整。梯度整体过大时，可以按比例缩短它，避免一次走得太猛。停一下：裁剪是不是把每个参数都设成相同值？不是，它限制的是这次更新依据的梯度大小，通常保留方向。到这里，一次学习已经闭环。接下来要解决的，是怎样让这个循环跨越海量文本和许多台机器。

画面公式：`g ← g × min(1, 阈值 / ||g||)`

参考：[17](https://arxiv.org/abs/2302.13971) · [30](https://arxiv.org/abs/1211.5063)

### 09 · 把一次学习放大到整个训练场

**25:35 · 训练循环真正开始**

到这里，我们已经能让一个参数朝正确方向移动。把镜头拉远，真实训练做的是同一件事，只不过同时移动数十亿个参数。先取一批句子，前向计算每个位置的预测，用真实下一个词计算损失，再反向传播，最后让优化器更新参数。随后换下一批句子，重新开始。注意，上一轮的梯度通常要清空，否则会无意中重复算旧账。这个循环里没有一位老师逐句讲解语法，文本本身就提供了大量预测题。

画面公式：`batch → forward → backward → step`

参考：[31](https://docs.pytorch.org/tutorials/beginner/basics/optimization_tutorial.html)

**26:08 · 显存装不下怎么办**

可是，一批数据太大，显存装不下怎么办？想象四个小组各交一份意见，等意见收齐再开一次决策会。梯度累积就是把大批次切成几个微批次，逐份计算梯度，累积后才更新一次参数。假设每份同样大，累积四份时要按整体目标正确求平均，而不是让更新突然变成四倍。这样节省一次需要存下的中间结果，却不会凭空减少全部计算量。小组规模、累积次数和并行机器数量，一起决定有效批次大小。

画面公式：`B_effective = B_micro × accumulation × DP`

参考：[32](https://huggingface.co/docs/accelerate/usage_guides/gradient_accumulation)

**26:42 · 数字也有存储成本**

显存里装的不只是文字，还有权重、梯度和中间向量。每个数都用很长的表示，会占空间，也增加搬运成本。混合精度让许多乘法采用较短的浮点数，同时把一些敏感计算或累积保留在较高精度。两种十六位格式并不相同：BF16 保留较宽的数值范围，FP16 对微小梯度更容易发生下溢。FP16 常用损失缩放，先放大、反传后再还原。缩放是保护数值，不能把它理解为让模型更重视某道题。

画面公式：`scaled_loss = s × loss; grad = scaled_grad / s`

参考：[33](https://docs.pytorch.org/docs/stable/notes/amp_examples.html) · [34](https://arxiv.org/abs/1710.03740)

**27:16 · 机器之间怎样分工**

当一台机器仍然不够，就要决定把什么拆开。数据并行让多台机器持有模型副本，各看不同数据，之后汇总梯度。张量并行把一个大矩阵切开，多台机器协作完成同一次乘法。流水线并行则把不同层交给不同机器，像接力处理微批次。实际系统经常组合这些方法，也会分片保存优化器状态。这里的难题逐渐从怎么算，变成计算时谁在等待、机器之间搬运多少数据。机器翻倍，速度并不会自动翻倍。

画面公式：`speed ≠ GPU count`

参考：[35](https://arxiv.org/abs/2104.04473) · [36](https://arxiv.org/abs/1910.02054)

**27:51 · 给长跑留下路标**

训练持续很久，断电或程序错误都可能让进度中断。检查点像游戏存档，但为了真正接着训练，往往不能只存模型权重，还要存优化器状态、当前步数，必要时包括随机状态和数据进度。另一条曲线来自验证集：暂时停下参数更新，让模型做没有拿来训练的题。如果训练损失下降，验证表现却恶化，就要排查过拟合、数据变化或评估问题。验证集一旦混进训练数据，这块仪表盘就可能开始报喜不报忧。

画面公式：`checkpoint ≠ weights only`

参考：[37](https://docs.pytorch.org/tutorials/beginner/saving_loading_models.html) · [1](https://arxiv.org/abs/2005.14165)

**28:25 · 预算该花在哪儿**

最后问你一个问题：预算固定，参数翻倍一定更好吗？停一下想想。参数更多，每处理一个词通常也更贵，结果可能只能学习更少文本，反而没有充分训练。研究因此寻找模型规模、训练词数与算力之间的合适配比，这就是缩放规律的一种用途。但经验曲线有适用范围，还会受数据质量、架构和部署成本影响。若产品要服务海量请求，团队也可能选择更小的模型、训练更久，用一次训练成本换长期更便宜的推理。

画面公式：`C ≈ 6PD（P 参数量，D 训练词元数；稠密模型）`

参考：[38](https://arxiv.org/abs/2203.15556) · [17](https://arxiv.org/abs/2302.13971)

### 10 · 从会续写到会当助手

**28:59 · 预训练还没有结束故事**

预训练之后，模型已经从预测任务里学到大量语言和世界规律，但给它一个问题，它仍可能接着编写另一道问题。因为续写文本和充当助手，目标并不完全相同。现在把数据换成用户提问与理想回答的对话，让模型继续做下一词预测，这叫监督微调。网络主干通常没有突然换成另一种机器，主要改变的是样本分布和训练目标的具体用法。我们在告诉同一个模型：遇到这种对话情境，接下来应当怎样回应。

画面公式：`pretraining → SFT`

参考：[39](https://arxiv.org/abs/2203.02155)

**29:32 · 只给回答部分记分**

看这段对话：用户问，小猫为什么坐在地毯上？助手答，因为地毯柔软。训练时仍然输入前文、预测后文，不过一种常见做法是只对助手回答的词计算损失。用户问题依然作为上下文参与前向计算，只是那些位置不直接计入损失。注意，这个损失掩码与前面防止偷看未来的注意力掩码，管的是两件事。前者决定哪些预测被评分，后者决定每个位置能读取哪里。把两者分清，你就能读懂许多微调代码。

画面公式：`L = sum(mask × token_loss) / sum(mask)`

参考：[40](https://huggingface.co/docs/trl/sft_trainer)

**30:07 · 示范之外还有偏好**

但是，一道开放问题往往有多种好答案，很难只指定一篇标准作文。我们可以让模型生成两个回答，请人比较哪一个更有帮助、更准确。这样的偏好对可以训练奖励模型，让它为问题与回答给出一个分数。奖励模型也会犯错，它学到的是标注数据中的偏好规律，不是一台真理检测器。如果标注员经常偏爱长篇回答，系统就可能学到越长越好的捷径。因此，偏好标准、样本覆盖与分歧处理，本身就是训练设计的一部分。

画面公式：`P(A > B) = sigmoid(rA − rB)`

参考：[39](https://arxiv.org/abs/2203.02155) · [41](https://arxiv.org/abs/2210.10760)

**30:41 · 让模型尝试再调整**

有了奖励，便可以让当前模型实际写出回答，收到分数，再调整以后生成类似回答的倾向。这条路线是强化学习。经典的人类反馈方案常用近端策略优化，简称 PPO。它限制每次策略更新过大，还常加入与参考模型之间的差异惩罚，避免为了刷奖励分数偏离太远。这里的人类通常先提供比较数据，训练出评分器，不必坐在旁边给每个生成步骤打分。模型尝试、环境评价、参数更新，组成一个新的训练循环。

画面公式：`maximize E[reward] − β × KL`

参考：[42](https://arxiv.org/abs/1707.06347) · [39](https://arxiv.org/abs/2203.02155)

**31:17 · 比较答案也能直接学**

还有一条更直接的路线。既然手里已经有好回答和较差回答，能不能直接用这对数据调整语言模型？直接偏好优化，简称 DPO，就是这样做的。它比较模型给两个回答的相对概率，同时借助固定参考模型来衡量变化，再构造可反向传播的损失。标准做法不必单独训练一个奖励模型，也不需要在每一步训练现场生成新回答。不过，数据来源和比较是否可信，依然决定它学向何处。省去工程环节，不等于偏好质量不重要。

画面公式：`DPO: preference relative to reference`

参考：[43](https://arxiv.org/abs/2305.18290)

**31:53 · 奖励必须来自人吗**

现在想一想：训练模型解数学题，一定要让人给每段思考打分吗？答案是否定的。若最终答案能核验，或者代码能运行测试，程序就能提供可验证奖励。模型尝试不同解法，训练算法提高获得奖励的行为倾向。它仍可能利用测试漏洞，也可能写出不可靠的解释，所以通过有限测试不等于全面正确。这说明强化学习是一种优化方式，人类偏好和程序判分是不同的奖励来源。这些后训练方法可以组合，训练顺序也不唯一。

画面公式：`sample → verify → update`

参考：[44](https://arxiv.org/html/2501.12948v1)

### 11 · 模型走进产品之后

**32:27 · 第一次等待在做什么**

训练告一段落，把参数固定下来，模型就可以接待真实请求了。输入一段很长的材料时，它通常先处理整段提示词，这个阶段叫预填充。每个位置只能读取当前位置及此前的信息，但已知位置可以在同一层里并行计算。接着进入逐词解码：根据末尾位置的预测产生一个新词，再把新词接回上下文继续计算。等待第一个字，与后面每秒出现多少字，是两种体验指标。输入很长和回答很长，增加成本的方式也有所不同。

画面公式：`prefill(prompt) → decode(token by token)`

参考：[45](https://huggingface.co/docs/transformers/cache_explanation) · [46](https://arxiv.org/abs/2309.06180)

**33:02 · 别重复计算旧信息**

但每写一个字，真要把整篇前文从头算一遍吗？还记得因果掩码吗，旧位置看不到未来，所以新词出现不会改变旧位置已经算好的键和值。我们把每一层的这些结果存起来，形成键值缓存。生成下一词时，只计算新位置的查询、键和值，再读取旧缓存做注意力计算。这样省掉大量重复工作，代价是缓存会随着上下文变长而占用更多显存。它保存的是这次请求的中间计算，不是把你说的话永久写进模型参数。

画面公式：`K_cache ← [K_cache; k_new]`

参考：[45](https://huggingface.co/docs/transformers/cache_explanation)

**33:36 · 同一模型不同回答**

模型输出的是分数和概率，产品还需要决定怎样选出下一个词。温度会在归一化之前缩放分数：较低温度通常让高分候选更突出，较高温度让分布更平缓。核采样则先按概率排序，只保留累计概率达到指定阈值的最小候选集合，再重新归一化抽取。因此同一模型回答同一问题，也可能产生不同答案。这里调节的是生成的随机性，不是在调节事实真实性。错误答案即使被稳定重复一百次，也没有因此成为正确答案。

画面公式：`p = softmax(logits / T)`

参考：[47](https://arxiv.org/abs/1904.09751) · [48](https://huggingface.co/docs/transformers/main_classes/text_generation)

**34:11 · 多想一会儿意味着什么**

如果让模型先分解问题、检查中间结论，再给答案，额外生成的内容就给后续计算增加了可利用的上下文。也可以生成多条解法，再用规则或模型筛选。这些方法增加的是推理时的计算预算，不意味着回答期间正在执行梯度下降。参数可以一直保持不变，而任务表现因计算路径不同而变化。经过相应训练的模型，可能更善于利用这些额外步骤，但文字更长并不自动代表推理更好，仍要用最终结果和可靠评估来判断。

画面公式：`more inference compute ≠ parameter update`

参考：[49](https://arxiv.org/abs/2201.11903) · [50](https://arxiv.org/abs/2203.11171)

**34:44 · 查资料不等于重新训练**

现在产品希望回答公司内部的问题，但知识库每天都在变。常见办法是先检索相关材料，再把材料放进模型上下文，这就是检索增强生成。若需要计算或查订单，则让模型生成工具调用，由程序执行，再把结果送回来。正常使用这些能力时，模型参数可以完全不变；变化的是它这一次看到了什么、获得了什么外部结果。工具能力和检索器可以经过训练，但一次查资料，不会自动变成一次模型训练。

画面公式：`answer = model(question + retrieved context)`

参考：[51](https://arxiv.org/abs/2005.11401) · [52](https://arxiv.org/abs/2302.04761)

**35:16 · 便宜一点的改造方法**

最后一道判断题：微调和量化是在做同一件事吗？不是。低秩适配冻结原权重，只训练两块较小矩阵，用它们的乘积表示权重增量，相当于学习一条较省参数的调整通道。量化则用更少位数表示数值，目标是减小存储和搬运成本，实际速度还取决于硬件支持。两种方法可以结合，却解决不同问题。前者让模型适应任务，后者改变部署时的数值表示。是否划算，要同时检查效果损失、显存需求和真实请求延迟。

画面公式：`LoRA: W_new = W + BA`

参考：[53](https://arxiv.org/abs/2106.09685) · [54](https://arxiv.org/abs/2210.17323)

### 12 · 什么时候才算训练完成

**35:53 · 没有一张万能毕业证**

训练什么时候才算完成？没有一个损失值，跨过它就突然毕业。团队通常在预算、效果和产品要求之间选择检查点。验证损失告诉我们预测能力有没有改善，任务测试检查它能否完成具体工作，人工评估观察回答是否清楚、有用，安全测试寻找危险失误。加上延迟与成本，才接近产品要求。一个模型可能在写代码上进步，同时在表达或某类任务上退步，因此平均分上涨，并不能替代对关键场景逐项检查。

画面公式：`quality = a set of measurements`

参考：[55](https://arxiv.org/abs/2211.09110)

**36:27 · 高分是不是见过原题**

假设模型在一道题上答得完美，我们还得问：它是不是早就见过题目和答案？训练语料可能从公开网页收集，公开评测也可能被转载进去，于是考试变成了背题。留出数据、检查重复、设置新的题目，都是为了减少这种污染。还要注意，同一份评测若被反复用于挑模型，它也会逐渐参与我们的选择过程。因此，开发阶段可以用验证集调整方案，最终仍应保留独立的测试或真实场景检验，让分数更接近面对新问题的能力。

画面公式：`seen questions ≠ generalization`

参考：[1](https://arxiv.org/abs/2005.14165) · [56](https://arxiv.org/abs/2310.17623)

**37:02 · 用实验定位原因**

如果新版本回答变啰嗦，能直接断言是模型架构出了问题吗？我们可以提出几个候选原因：训练样本偏长，奖励偏爱详细回答，或者推理配置改变了。接着只改一个因素，保持其他条件一致，观察结果，这就是消融实验的基本想法。比如固定模型和提示词比较采样设置，再固定训练预算比较两种偏好数据。它未必一次找到全部原因，却能把合理的故事，转变成可以支持或推翻的假设。产品判断也能这样参与技术讨论。

画面公式：`same setup + one controlled change`

参考：[39](https://arxiv.org/abs/2203.02155) · [41](https://arxiv.org/abs/2210.10760)

**37:36 · 主干之外还有分支**

我们一路使用的是稠密的解码器模型，但这张地图还有分支。例如混合专家把某些前馈层换成多个专家网络，让路由器为每个词选择其中一小部分参与计算。于是总参数量很大，每个词实际激活的参数却少得多。这里的专家通常是训练出来的功能分工，并不天然对应数学家、作家这些人类职业；还要解决负载均衡和通信问题。多模态、蒸馏与其他注意力变体也各有课程。掌握主干后，再看它们改变了哪一个环节。

画面公式：`MoE: many experts, few active per token`

参考：[57](https://arxiv.org/abs/2101.03961)

**38:10 · 把整条路径重新走一遍**

现在让小猫坐在这几个字，再走一遍完整旅程。文本被切成词元，词元编号查出向量。向量经过注意力交换上下文信息，经过非线性前馈层变换，层层累积后变成词表上的分数。训练时，我们拿地毯这个真实目标计算损失，沿计算路径反向分配梯度，再更新参数。海量重复形成基础模型，示范、偏好或可验证奖励进一步塑造行为。部署时固定参数，输入上下文，生成下一个词。最初看起来神秘的过程，现在已经能逐段追踪。

画面公式：`data → prediction → loss → gradient → weights`

参考：[14](https://arxiv.org/abs/1706.03762) · [39](https://arxiv.org/abs/2203.02155)

**38:46 · 以后遇到新名词时**

以后遇到新名词，先问四句话：它改变模型读到的数据吗？改变内部计算结构吗？改变怎样评分和更新参数吗？还是只改变推理时使用的上下文与计算预算？这些问题把复杂系统重新放回地图。我们还没有穷尽每一种算法，也没有证明语言理解为何涌现，但已经看见一条可实现、可检查的训练路线。理解大模型的第一步，是知道每一环在计算什么，以及证据能支持到哪里。接下来读论文，就有地方安放新知识了。

画面公式：`data / architecture / objective / inference`

参考：[14](https://arxiv.org/abs/1706.03762) · [55](https://arxiv.org/abs/2211.09110)

## 术语速查

| 术语 | 一句话回忆 |
| --- | --- |
| Token / 词元 | 分词器定义的文本块，不必等于一个汉字或完整单词。 |
| Embedding / 嵌入 | 用编号查出一行可学习数字，作为该词元的初始向量。 |
| 参数 / 激活值 | 参数是模型的可学习数字；激活值是一次前向计算产生的中间结果。 |
| 点积 / 加权和 | 点积把两串数字变成一个匹配分数；加权和按比例混合多串数字。 |
| Q / K / V | 查询与键计算信息读取权重，权重用来混合值向量。 |
| Softmax | 把一排分数变成非负且总和为一的权重；其数值本身不保证事实正确。 |
| Causal mask | 每个输入位置只允许读取自身和此前位置，避免预测下一词时偷看答案。 |
| RoPE | 旋转查询与键的坐标对，让点积带上相对位置关系。 |
| FFN / 残差 / Norm | 逐位置做非线性加工 / 保留直接相加路径 / 控制向量数值尺度。 |
| Logits | 词表上的未归一化分数，经过 softmax 后才得到下一词概率。 |
| 交叉熵 | 本课程单个目标位置的损失为负的正确词概率自然对数。 |
| 梯度 / 反向传播 | 梯度描述损失对参数的局部变化率；反向传播高效计算这些变化率。 |
| AdamW | 利用梯度及梯度平方的移动估计调节更新，并解耦权重衰减。 |
| SFT | 使用示范回答继续训练，常只对助手回答部分计损失。 |
| RLHF / DPO | 经典 RLHF 可训练奖励模型再做强化学习；标准 DPO 直接使用成对偏好与固定参考模型构造损失。 |
| KV cache | 缓存当前请求中各层已计算的键和值，减少逐词解码的重复计算。 |
| RAG / 工具 | 把检索材料或程序执行结果放进上下文；日常调用本身不更新模型参数。 |
| LoRA / 量化 | 前者学习低秩参数增量；后者用较少位数表示数值，两者可以结合。 |
| MoE | 路由器让每个词元仅使用部分专家网络，总参数量与每词激活参数量可以不同。 |
