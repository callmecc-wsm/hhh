## 具体修复

| 问题 | 修复 |
| --- | --- |
| 正确选项几乎总在同一位置 | 构造章节时稳定重排；选项、案例反馈与正确索引一起变化。诊断题正确位置分布为 24 / 24 / 24，案例为 12 / 12 / 12 |
| 干扰项只需排除明显荒谬答案 | 改为真实误解，例如把格式合法当作授权、把教师模板增益外推为业务迁移、把更多候选当作更多独立任务 |
| 低秩、sigmoid、原子操作对新读者不够具体 | 分别解释为“最多 r 个可组合方向”“把分数压到 0～1”“检查与认领不可被其它请求插入的整体” |
| DPO 易被理解为只提高优选绝对概率 | 补充完整回答的 log 概率、固定参考模型与相对概率比；加入两回答都提高但偏好间距恶化的计算题 |
| T² 容易被理解为精确消除温度影响 | 明确教师与学生使用同一温度的前提；缩放补偿梯度通常缩小的趋势，并不保证各温度梯度相等 |
| 单位置蒸馏易被外推为完整任务成功 | 补充给定示范前缀与学生自生成前缀的差异，以及完整生成和偏离后恢复的验证需要 |
| 幂等键只绑定订单号可能误合并多次合法退款 | 改为具体动作 ID，并说明同键参数一致性、原子认领、持久状态和跨进程竞态 |
| 多 Agent 预算遗漏协调成本 | 明确主流程开销与子任务预算共同受总预算约束 |
| 审批被误解为不断重复确认 | 说明已明确授权且参数未变的动作不必无谓重复审批；权限范围与产品风险策略仍需检查 |
| 教学世界与成熟框架的事实边界 | Pi 源码标为未锁定版本的延伸阅读，避免声称复刻或核验最新实现；本地脚本不代表真实模型生产可靠率 |
| Harness 案例数量 | 正文统一使用包含取消情景的 16 个固定案例 |

## 验证方式与边界

- **程序检查**：使用 Node 24 原生 TypeScript 支持执行课程数据。临时副本仅将本地 import 补为 `.ts` 扩展名；未改动课程数据逻辑。断言课程及章节数量、题目数、选项数、索引范围、文本非空、词条唯一性与所有章节关联。
- **重排检查**：单独构造已知正确答案和已知反馈的章节，验证重排后仍指向同一语义答案，三个案例反馈始终与各自选项配对。
- **计算检查**：手算表达再用独立公式断言复核，包括两个 softmax 温度结果、单权重更新、LoRA 参数数与比例、有效平均损失、召回率和回本周期。
- **构建边界**：本审查不把 Node 的类型剥离执行称为完整 TypeScript 类型检查；项目类型检查、浏览器测试及模拟引擎测试由对应验证流程覆盖。
- **教学边界**：基础识别、迁移判断和独立复述形成递进，但本轮没有真实学习者试验，不能声称已实证达到最佳学习效果。已读、全题正确和流程完成均不是专业能力认证。
- **来源边界**：所有课程引用在本轮均未逐页在线核验。论文、官方文档与开源项目作为延伸阅读；滚动 API、源码、价格与服务条款必须按实际使用版本复核。引用不证明本工坊模拟值，也不表示对任何闭源模型内部机制的确认。

课程编辑后需重新运行 `public/workshop/export-handbook.mjs` 和 `public/workshop/package-materials.py`，使下载讲义与资料包使用相同内容版本。
