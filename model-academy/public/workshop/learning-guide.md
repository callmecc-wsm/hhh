# 模型工坊学习指南

**目标**：能够解释机制、预测变化、核对证据，并把方法迁移到没见过的问题。完成章节、命中练习答案、勾选自评，都不等于能力认证。

**课程关系**：预训练建立通用能力；微调改变已有模型的行为；蒸馏把教师提供的训练信号传给学生；Agent Harness 负责把模型建议接到受控行动上。蒸馏可以使用微调，Harness 可以接入微调后的模型，它们不是互斥的产品分类。

## 从自己能回答的问题出发

| 你现在的问题 | 先学哪里 | 学完需要拿出什么 |
| --- | --- | --- |
| 模型为何会预测下一个词？ | 已有的从零训练课程 | 用输入、参数、损失、梯度解释一次训练更新 |
| 一个模型怎样稳定遵守领域流程？ | 微调工坊 | 一个训练数据方案、隔离评测方案、基线对照 |
| 公司怎样用教师模型改善较小的学生？ | 蒸馏工坊 | 有授权依据、可用信号、覆盖矩阵、独立评测的试验方案 |
| 模型说了要退款，程序怎样可靠执行？ | Harness 工坊 | 一条可回放轨迹和能在故障下成立的执行规则 |

**预备知识**：不需要先会写代码。遇到概率、交叉熵、梯度时，先理解它们各回答什么问题，再看公式中的每一项。代码用于追踪机制，不是入门门槛。

## 一轮学习怎样进行

| 环节 | 你要做的事 | 留下的记录 |
| --- | --- | --- |
| 先想 | 阅读本章问题，写出直觉解释 | “我认为会发生什么，因为……” |
| 找机制 | 读概念和具体例子，指出数据、模型、控制层分别做什么 | 一张因果箭头图或三句话 |
| 做预测 | 在运行前说清一个变量的变化方向 | “只改变 X，预计 Y 增大，Z 不变” |
| 取基线 | 运行原始设置，记录数据来源、参数和结果 | 一条可复现的基线 |
| 做对照 | 一次只改变一个条件，重新运行 | 第二条结果及与基线的差别 |
| 查差异 | 预测不符时，定位最早出现差异的环节 | 原因、证据、下一次区分原因的试验 |
| 换场景 | 保留机制，换一个业务对象或边界条件 | 一道未见问题的解决过程 |
| 合上材料 | 用自己的话讲给没学过的人听 | 解释、反例、仍不确定的一点 |

**节奏**：每次学一章或一个机制，约 25–45 分钟；时间只是安排建议。能解释清楚再继续，比赶完章节更有用。两次对照都没有新发现时，先写出还缺哪条信息。

## 先认清实验里的数值

| 标记 | 真正执行了什么 | 可以支持的判断 | 不能据此判断 |
| --- | --- | --- | --- |
| 公式计算 | 按已声明输入计算损失、费用、显存、区间等 | 在这些假设下公式给出什么结果 | 商业模型当前价格或实际效果 |
| 真实微型训练 | 实际计算梯度并更新少量参数 | 标签、学习率、目标分布怎样影响这个小模型 | 完整 Transformer 的训练曲线或能力 |
| 固定情景推演 | 根据提前编写的样本与条件展示结果 | 一个决策为什么符合或违反本例的条件 | 任意真实场景必然有相同收益 |
| 本地状态机 | 脚本模型发请求，工具改变模拟世界 | 控制逻辑和本地副作用是否按规则发生 | 真实模型在开放输入上的可靠率 |

**核验习惯**：先读实验假设，再读结果；查清单位和分母；区分训练集、验证集、测试集；区分候选条数和独立问题数；区分模型说出的结果和工具返回的事实。

## 不用术语堆砌的解释法

一段完整解释至少交代五件事：输入是什么、变化在哪里、变化由什么驱动、如何发现做错、在什么情况下不成立。可以画图、举例或逐步演算，不要求固定措辞。

| 主题 | 不够充分的解释 | 更可检查的解释 |
| --- | --- | --- |
| 微调 | “用数据让模型更专业” | “输入仍包含问题，但只对助手目标位置计分；梯度更新参数；用未见客户任务检查是否学会流程” |
| 蒸馏 | “把大模型缩小” | “教师给出可用的输出或软分布，学生用这些信号更新参数；受任务覆盖和学生容量限制” |
| Harness | “让 Agent 自己做事” | “模型提出工具请求，程序校验权限与参数，必要时等待审批，执行后保存回执，再决定下一步” |

**自查**：解释里如果只有术语，补一个具体样本；如果只有比喻，补出比喻失效的地方；如果只有结论，补一条可观察证据。

## 三组可直接开始的对照

| 课题 | 基线 | 干预 | 运行前的预测题 | 核对证据 |
| --- | --- | --- | --- | --- |
| 标签噪声 | 干净标签，60 步，学习率 0.3 | 只把 4 条目标标签全部翻转 | 训练损失下降，是否仍可能让真正目标变差？ | 训练损失与干净目标集损失分别比较 |
| 教师软目标 | 只学硬标签，60 步，温度 2 | 只把软目标权重改为 1 | 次优答案的相对概率会发生什么？ | KL、四类分布，以及 T=1 的学生分布 |
| 退款回执丢失 | 正常提交并返回回执 | 只改成提交之后超时 | 超时能否证明没有退款？下一步能否重新退？ | 账本条数、实际退款调用次数、状态查询事件 |

**归因顺序**：输入和标签 → 目标定义 → 切分与泄漏 → 参数与计算 → 执行权限 → 外部状态 → 评测方式。尽量找最早偏离的环节。多个变量同时变动时，先承认无法分辨单独原因。

## 本地代码怎样运行

**环境**：Python 3.10 或更新版本即可。所有 Python 文件只使用标准库；不需要安装模型、GPU、API Key 或第三方包。文件保存到同一目录后，在该目录打开终端。

```bash
python3 fine_tune_and_distill.py --experiment compare
python3 fine_tune_and_distill.py --experiment finetune --steps 60 --noise 4
python3 fine_tune_and_distill.py --experiment distill --steps 50 --alpha 1 --temperature 2
python3 mini_harness.py --scenario normal
python3 mini_harness.py --scenario timeout
python3 mini_harness.py --scenario injection
python3 mini_harness.py --scenario unresolved
python3 -m unittest -v test_mini_harness.py test_training.py
```

**Windows**：若 `python3` 不存在，将命令开头替换为 `py -3` 或已安装的 `python`。

**演示审批**：命令行的正常和超时案例明确模拟“用户已经批准展示的参数”。它不是实际询问你的付款授权，也不会付款。网页案例须由你点击具体审批；真实产品要把此方法接到可信的用户确认路径。

**保留模拟账本**：加 `--db teaching.sqlite`，即可在进程退出后保留 SQLite 记录。重复运行相同任务不会再次产生同业务键的效果。默认使用内存，进程退出后记录消失；换一个新的文件可从空账本重新实验。

```bash
python3 mini_harness.py --scenario timeout --db teaching.sqlite
python3 mini_harness.py --scenario normal --db teaching.sqlite
```

**状态差异**：持久账本只保留提交证据，不会保存整个对话、模型游标或待审批状态。示例能够核对已提交动作；完整的跨进程任务恢复仍需持久化任务状态、审批生命周期和恢复策略。

## 从零读 Harness 的顺序

| 阅读位置 | 先回答的具体问题 | 观察或修改 |
| --- | --- | --- |
| `Message`、`parse_response` | 用户、模型、工具的消息由谁决定身份？ | 在模型响应里伪造 `role: system`，检查是否被拒绝 |
| `Model`、`ScriptModel` | 模型在这条链路里承诺提供什么？ | 把一个脚本请求换成错误参数，观察控制层 |
| `ToolCall`、`validate_call` | 格式正确为什么仍可能没有权限？ | 比较金额字符串、负数、超额金额、他人订单 |
| `Harness.step`、`observe` | 一次请求怎样进入执行，再回到上下文？ | 对照 `proposal`、`tool_start`、`observation` 事件 |
| `approval_digest`、`approve`、`reject` | 批准 50 元，为什么不能执行 90 元？ | 阅读参数变更测试，观察审批摘要不匹配 |
| `execute`、`cancel` | 模型一直要求继续时，谁能真正停止？ | 用 `budget`、`cancel` 案例核对实际调用次数 |
| `Ledger.refund`、`recover` | 提交成功但回执丢了，怎样恢复？ | 对照 `timeout` 与 `unresolved` 的终止状态 |
| `test_mini_harness.py` | 最终回答正确，是否可能仍然操作错误？ | 查账本、调用轨迹、越权工具执行数 |

**最终文字的边界**：Python 示例保留一个刻意可见的缺口：`done` 只代表模型输出了最终回答，不自动证明回答真实。测试会展示“模型说已退款、账本却为空”。网页的结果核验实验继续讨论如何给具体任务定义外部证据。通用地判断自然语言结论，需要额外评估和业务验证。

**注入防护的边界**：测试假设模型已经被文档里的恶意内容误导，然后检查能力白名单与授权范围是否阻止越权动作。它没有实现通用恶意文本检测器，也不能阻止所有通过合法工具发生的信息泄漏。真实系统还需参数级数据流策略、敏感信息控制和开放输入评测。

**生产化缺口**：真实模型适配器、网络超时与重试退避、并发取消、跨服务事务、身份与审批服务、任务持久化、敏感日志处理，都需要单独设计。这里的 SQLite 账本验证的是本地服务内事务与唯一键，不代表分布式系统里的绝对恰好一次。

## 从零读微型训练的顺序

| 阅读位置 | 要回答的问题 |
| --- | --- |
| `sigmoid`、`softmax` | 怎样把任意分数变成概率？为什么 softmax 先减去最大值？ |
| `linear_fit` 的三组数据 | 哪些标签被翻转？为什么评估的干净目标集不能跟着改？ |
| `error = probability - label` | 一个样本预测偏高，梯度把参数往哪推？ |
| `distill_gradient` | 硬标签与软目标分别提供什么信号？T² 为什么留下梯度里的 T？ |
| `distill_fit` 的两组学生概率 | 训练温度下的概率，为什么不能直接当作 T=1 上线行为？ |
| `test_training.py` 的有限差分 | 不照抄实现，怎样独立核验梯度方向和大小？ |

**与网页一致**：初始权重、合成数据、教师 logits、更新公式与网页微型实验一致；Python 和 JavaScript 的浮点实现可能在末位产生差异。两者均不以小模型结果预测实际 LLM 收益。

**下一步**：读完微调的损失掩码，再读讲义中的「看着学生一点点靠近」。前者解释“给定正确前缀，预测下一 token”；后者继续追问“学生上线时接着自己的输出写下去，一步偏离后会怎样”。用一个两步任务，分别记录正确前缀条件下的下一步分数和学生自由生成到结束的成功情况。两种评测回答不同问题，不能用前者替代后者。详见[完整讲义](complete-handbook.md)。

## 把知识带到新问题

| 迁移题 | 需要保留的机制 | 故意变化的条件 |
| --- | --- | --- |
| 电商客服变为医院预约 | 隔离测试、数据授权、流程一致性 | 错误后果、隐私范围、必须人工处理的边界 |
| 教师文本答案变为可见概率 | 教师信号来源、学生容量、独立评测 | 可用训练目标与词表对齐要求 |
| 模拟退款变为发送客户邮件 | 精确审批、稳定业务键、状态查询、取消语义 | 邮件已发出的不可撤回性质与服务端能力 |
| 单 Agent 变为多个子任务 | 总预算、最小权限、证据汇总 | 并行依赖、取消传播、结果冲突 |

**迁移自查**：指出一个必须改的地方和一个不该改的原则。只换了业务名词、没有重新检查约束，仍不算完成迁移。

## 间隔回顾与学习记录

**建议时点**：学完当晚用 3 分钟回忆；约 2 天后重做一个预测；约 1 周后换场景解释。不是精确的记忆曲线处方，可以按自己的遗忘情况调整。

每次回顾先合上讲义。想不起来时再找对应内容；已经会讲的内容减少重复，把时间留给解释断点。几章之后，混合微调、蒸馏、Harness 的题目，练习判断应干预哪一层。

```text
日期 / 章节：
本章我能解释的问题：
原预测及理由：
基线设置与结果：
只改变的条件：
结果与预测的差异：
支持归因的证据：
仍无法排除的解释：
换一个场景后的判断：
一周后要再问自己的问题：
```

**文档协作**：可把本文件、完整讲义或上面的记录模板导入自己的云文档，再请同伴只读你的解释并提反例。资料包不会自动上传文档或发送消息。网页进度属于学习记录，不是标准化测验成绩。

## 怎样评估自己的理解

| 程度 | 可观察证据 | 下一步 |
| --- | --- | --- |
| 认识 | 看见术语能指出例子 | 不看材料说出机制 |
| 解释 | 能串起输入、变化、反馈与限制 | 在运行前预测一次干预 |
| 预测 | 对未运行设置给出方向和理由 | 用结果修正错误解释 |
| 排错 | 用轨迹或数据定位最早的偏离 | 设计能区分两个原因的试验 |
| 迁移 | 对新场景调整约束并保留原则 | 找一个反例，说明结论边界 |

**判断依据**：你留下的预测、对照和解释，比点击数量更有用。自评和固定情景测试只能提示学习进展；不能据此声称已经具备生产系统实施资格。
